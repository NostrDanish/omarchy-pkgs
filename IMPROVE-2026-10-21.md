# Improvement Deep-Dive — NostrDanish/omarchy-pkgs — 2026-10-21

Fork of omacom/omarchy-pkgs (the pkgs.omarchy.org package pipeline), current to upstream 2026-10-17. Upstream is a mature CI-driven repo: build-pr/publish/promote/sync workflows, R2 bucket + GPG signing, VOUCHED.td trust list.

## Top recommendations (ranked, with effort S/M/L)

1. **[S] Decide what this fork *is*, then disable the workflows that can't work here.** The pipeline assumes secrets this fork does not (and should not) have: `GPG_PRIVATE_KEY`, `R2_*` (upstream's bucket), `PKGS_BOT_TOKEN`, `BASECAMP_CHATBOT_URL`, plus self-hosted runner labels (`omarchy-builder` droplet pool, `namespace-profile-arm64-linux-apple-12x32`). On this fork:
   - `publish.yml`/`promote.yml`/`unpublish.yml` will fail on every `pkgbuilds/**` push to `master` — or worse, publish garbage if upstream-matching secrets are ever set. Disable them (Actions tab → disable workflow) or add an early `if: github.repository == 'omacom/omarchy-pkgs'` guard (S, do this first).
   - `sync-upstream.yml` (6h), `sync-rebuilds.yml` (6h), `track-branches.yml` (hourly) will open auto-PRs here forever. GitHub auto-disables schedules on inactive forks, but don't rely on it — same guard or delete (S).
   - If the fork's real purpose is recipes for omarchy-mobile's `[omamobile]` repo, say so in the README and strip the publish pipeline to a minimal build+sign flow targeting *your* bucket (M).
2. **[S] Add a `FORK.md`.** The repo currently reads exactly like upstream's README (which even instructs `gh workflow run ... -R omacom/omarchy-pkgs`). Anyone (including future-you) can mistake this for the real thing. Document: upstream remote, sync cadence, which workflows are intentionally disabled, what the fork is for (S).
3. **[S] Keep the fork close to upstream or archive it.** HEAD is 4 days old now; the value here is the recipes. A monthly `git fetch upstream && merge` habit, or a scheduled sync workflow (ironic but apt), keeps `pkgbuilds/` fresh without the publishing machinery (S).
